# React Native macOS client prototype

This prototype measures a native client for the existing ThinkRail Bun host. Hermes owns only local navigation and presentation state. The Bun host owns projects, workspaces, files, git, PTYs, and in-process Pi sessions. The RN app never loads Pi, runs a second host, or serves the web bundle.

The macOS app receives a loopback host URL through `THINKRAIL_NATIVE_HOST_URL` (default `http://127.0.0.1:43423`). The client paints its shell immediately, reconnects to `/ws`, checks `server.welcome`, reads authoritative host state, and applies relevant pushes. Failed startup connections retry every 25 ms for the first second so a concurrently starting host does not impose a 500 ms wait. After welcome or that startup window, retries use 500 ms; stopping cancels retries. On reconnection it rehydrates from the host. The browser wire in `packages/contracts` is the reference; this standalone prototype implements a small structural subset rather than a second contract source of truth.

Metro watches the contracts package so client-safe quota validation and bounds come from its public barrel; Central wire types are imported as types only. The standalone client uses Bun to install and run scripts. Metro transforms its JavaScript with SWC; the Debug app uses Fast Refresh for UI iteration, while benchmarks use a separately built Release app with no development server.

The workload includes project and workspace navigation; multiple chats with transcript hydration, prompt, streaming text and tool rows; file tree and plain-text file view; git changes and diff; spec list; terminal tab with real PTY input/output; and overview/status surfaces. The screen contains representative pane and row counts but no invented domain records. Local tab, pane, and selection state is disposable. The center tab bar keeps multiple file, diff, chat, and terminal tabs open; selecting a tab restores that resource, and closing one leaves the others available. Its terminal button opens the terminal beside chats and documents; the lower terminal region has separate controls. Tabs reset on workspace change. The Changes pane selects a host git scope and diff base, and switches between list and grouped tree views; the selected scope also applies when opening a diff. Editor and terminal rendering remain intentionally naive.

The default workspace screen follows ThinkRail's desktop frame: Projects on the left, a workspace canvas above the terminal region, and independent Specs/Files and Changes/Review groups on the right. Tasks and skills remain available through the upper group's add menu. Opening a file, chat, diff, or terminal switches only its local presentation tab. Its four palettes are generated from the web client's bundled themes. Appearance settings write the host preference, while fixed or system mode resolves a palette on this device; macOS appearance changes repaint the client without changing host state. The macOS window uses a full-size content view with the system traffic lights over the 40-point React Native header; AppKit retains window controls, resizing, and the application menu. The window enforces a minimum size and recovers an invalid saved frame after repeated launches.

The prototype is a client maquette, not feature parity. It omits the web client's docking, Monaco, xterm terminal emulation, full settings, review authoring, extension UI, keyboard shortcuts, and most dialogs. These omissions are client work, not evidence that their host capabilities can run inside Hermes. The host already provides filesystem access and watching, local sockets, subprocesses, and PTYs; rebuilding those in Hermes would require extensive native bridges or replacements.
